# VaneAI · 爆款一键复刻 · MVP

> Status: **DRAFT** — requirements only. Implementation planning pending via `/plan`.
> Created: 2026-06-02
> Source skill: `/ecc:plan-prd`

## Problem

自媒体短视频运营和独立游戏策划在小红书 / 抖音 / Liblib / 即梦灵感库看到爆款图后，想用同款风格做自己的内容。当前流程是反复改 prompt 半小时仍出不来想要的，或在 Liblib / 即梦灵感库找到模板但无法直接套用到自己的素材上。代价：30 分钟以上的时间黑洞、产出偏离预期、放弃复刻或者凑合发布。

## Evidence

- 用户原话：用户在小红书等平台高频出现"求 prompt"、"这是怎么做的"、"想要同款"等评论（用户确认见过很多）。
- 自身经历：项目发起人本人多次出现"想要复刻一张图，调 prompt 调半小时仍不是想要的结果"。
- 竞品不足：即梦灵感库存在更新跟不上的问题；Liblib 等模板广场提供模板但缺少"一键应用到我自己的内容"的最后一步。
- 量化数据：暂无。
- **Assumption — needs validation**：自媒体运营 + 独立游戏策划这两类目标用户对"一键复刻"的付费/留存意愿，需通过 MVP 上线后的 4 周用户数据验证。验证方法：W5 内测期间 3–5 个目标用户访谈 + W6 公开 beta 后看激活/留存指标。

## Users

- **Primary**：
  - 做短视频脚本封面的自媒体运营 — 触发场景：刷到爆款封面 → 想用同款风格做自己下一条内容的封面
  - 做角色概念图的独立游戏策划 — 触发场景：看到爆款角色概念图 / 盲盒手办图 → 想用同款风格做自己游戏的角色草稿
- **Not for**：
  - 已熟练写 prompt、追求最高自由度的 AI 创作老手（他们应该用 Midjourney / Liblib，VaneAI 不再加 prompt 自由度去抢这个人群）
  - 企业 / 团队协作场景
  - 开发者 API 调用方
  - 把 AI 生图当玩具的轻度爱好者（不是付费意愿来源）

## Hypothesis

我们相信，**一个由编辑精选、随爆款实时更新、支持"选模板 + 输入主体关键词 → 一键复刻同款风格"的爆款图模板库**，能解决 **"看到爆款图却复刻不出来、堆 prompt 半小时仍偏"** 的问题，服务于**做短视频/图文封面的自媒体运营和做角色概念图的独立游戏策划**。

我们将通过下面这件事确认假设成立：**MVP 上线后 4 周内，≥30% 注册用户至少完成 1 次"选模板 → 一键复刻"成功（成功定义见下），且 7 日留存 ≥20%。**

**复刻成功定义**：用户在选中模板后完成 1 次生成，且在结果展示后 60 秒内未点击"重试"按钮（视为对结果接受）。

## Success Metrics

| Metric | Target | How measured |
|---|---|---|
| 4 周内"完成 1 次成功复刻"用户占注册用户比例 | ≥ 30% | 后台埋点：`generation_succeeded` + 60s 内无 `retry_clicked` |
| 7 日留存 | ≥ 20% | 注册后 D1–D7 任意一天有 1 次生成视为留存 |
| 文生图 P50 出图时间 | ≤ 15 秒 | provider 调用耗时埋点 |
| 任务失败率 | ≤ 5% | `generation_failed` / `generation_attempted` |
| W6 末真实用户数 | ≥ 50 个完成至少 1 次生成 | 注册 + 至少 1 条成功 job |

## Scope

### MVP — 验证假设的最小集

**用户能做的核心 4 件事：**

1. **浏览爆款模板库** — 编辑精选，首批 30–50 条；按主题（游戏角色概念 / 盲盒手办风）分类筛选；缩略图 + 大图详情。
2. **一键复刻** — 选中模板 → 输入"主体关键词"（仅文本输入，不暴露 prompt）→ 生成。
3. **看到结果 + 下载 / 再次生成** — 结果展示、再次复刻（同模板换关键词）、下载图片。
4. **个人作品库** — 所有自己生成过的图，列表 + 详情 + 删除 + 「再次复刻」入口。

**配套必备（用户看不到但不可或缺）：**

- 邮箱 Magic Link + Google OAuth 登录
- 每日免费配额（默认 10 次）+ 注册赠送积分
- 任务失败自动回补积分
- 编辑后台（仅 admin）：模板上下架 / 任务列表 / 失败原因 / 用户列表
- 服务条款 + 隐私政策

**起步主题**：**游戏角色概念图 + 盲盒手办风**（双主题起步，不全品类铺开）。

**爆款来源信号**：第 1 周纯编辑主观挑选；第 2 周开始参考小红书 / 即梦灵感库 / Liblib 排行榜作为参考池。

**复刻精度策略**：偏向高度可控（"换主体"），而非灵感发散。同模板 + 同关键词产出应在视觉上接近原图风格。

### Out of scope — 显式不做

| 不做 | 为什么 |
|---|---|
| 自由 prompt 输入 | 会混淆产品定位（方向 B 的灵魂是"用户不需要懂 prompt"），且让产品和 Midjourney/Liblib 直接撞 |
| 上传参考图复刻 | V2 再做；MVP 先验证"模板 + 主体关键词"是否够 |
| 任何视频功能（图生视频、文生视频） | V2/V3 才启动；MVP 期间不写一行视频代码 |
| UGC 模板上传 | 冷启动期没有用户也就没有内容 |
| 支付 / 订阅 | 先验证留存数据，有 PMF 信号再接 |
| 社区 / 广场 / 点赞 / 评论 | 不是 MVP 护城河 |
| 多语言 i18n | 中文 web 响应式起步 |
| 移动端 App / 小程序 | Web 响应式覆盖足够 |
| 模板自动从外网抓取 | 版权 + 反爬风险高；爆款来源已锁人工编辑 |
| ControlNet / LoRA / 训练 / Inpainting | 与"一键复刻"承诺冲突 |
| Prompt 优化器 / AI Agent | 用户要"能用"而非"很 AI" |

## Open Questions

- [ ] **核心数据验证**：4 周内 ≥30% 用户完成成功复刻 + 7 日留存 ≥20% 的假设是否成立？验证方法：W6 公开 beta 后 4 周观察。
- [ ] **付费意愿**：免费配额耗尽时用户是否愿意付费？验证方法：W6 后看用户主动询问频次 + 流失原因调研。
- [ ] **模板更新频率与覆盖**：每周 +5 条新模板是否够？是否需要按主题 + 风格双轴扩展？验证方法：W7 后看用户对"想要的风格找不到"反馈量。
- [ ] **复刻精度落地**：模型默认参数能否实现"高度可控复刻"？需要 W2 单次闭环时通过实测确定 fal.ai 上具体模型 + 参数（候选：flux-dev / flux-pro / sdxl + LoRA 风格化），但 LoRA 是否引入**仍需评估是否破坏"一键"承诺**。
- [ ] **关键词输入的引导设计**：用户输入"穿西装的男生"还是"穿西装、深色背景、电影感、男生"？是否需要在模板详情里给"建议关键词"预填？属于 UI/UX 决策，移交 `/plan` 或 frontend-design skill。
- [ ] **核心页面形态**（用户原始需求第 4 项）：首页 = 模板广场？还是 = 作品库？登录后默认落点应是哪个？属于 implementation detail，移交 `/plan`。
- [ ] **运营节奏**：1 名运营每周稳定产出 5 条新模板（含参考图 + base prompt + 推荐尺寸 + 示范产出）的工作量是否现实？需 W1 试运营 1 周确认。

## Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| 模板内容版权问题（参考图使用爆款截图） | High | Critical | 仅使用编辑团队自行生成的参考图，或购买授权图库；不直接使用从小红书/抖音抓取的他人作品 |
| "一键复刻"产出偏差大，用户感知"被骗" | Medium | High | W2 单次闭环时实测复刻精度；不达标先调模型参数，仍不达标重新审视 hypothesis |
| 编辑运营节奏跟不上，模板库 W4 后停滞 | Medium | High | W1 试运营 1 周确认产出节奏；建标准化模板录入流程；预留 1 周 buffer |
| Provider（fal.ai）服务抖动 / 涨价 | Low | Medium | Provider 抽象层已留备选位（`lib/providers/replicate.ts`）；有问题切 Replicate |
| 用户实际不在意"风格复刻"，只想要好图 | Medium | Critical | W5 内测访谈 + W6 公开 beta 4 周数据观察；不达 hypothesis 阈值则评估转向 |
| Vercel function 超时 / Supabase 免费额度耗尽 | Low | Medium | 异步任务全走 Inngest 不放 Vercel function；Storage 用量监控 + 软删定时清理 |
| 涉黄涉政内容生成 | Medium | High | 依赖 fal.ai 默认安全过滤 + 关键词黑名单；用户协议明示责任 |
| 自由 prompt 用户不愿用受限输入而流失 | Medium | Medium | MVP 严格不给自由 prompt 入口，依赖产品定位 + 受众选择；W6 后看流失原因决定是否加"高级"入口 |
