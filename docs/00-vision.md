# 00 · 产品愿景

> ⚠️ 2026-06-02 重大变更：产品方向从"通用文生图"收窄为"**爆款一键复刻**"。详见 [CHANGELOG.md](./CHANGELOG.md)。

## 项目代号

**VaneAI** — 一句话定义：**让看到爆款图的人，一键复刻同款风格的工具。**

## 核心价值主张

> "你看到的爆款，你也能做出来——不用懂 prompt，输入你的主体关键词就行。"

VaneAI **不是**通用 AI 创作工具（那是 Midjourney / Liblib / 即梦的赛道）。
VaneAI **是**针对"看到爆款想复刻"这一具体场景设计的产品。

## 长期方向（按时间序）

| 阶段 | 能力 | 时间预期 |
|------|------|---------|
| V1 | **图片爆款一键复刻** | W1 - W6 |
| V2 | 上传参考图复刻 + 图片爆款变视频（image → video） | W7 - W12（预计） |
| V3 | 视频爆款一键复刻（text/image → video） | V2 之后 |

**所有阶段共享同一个产品灵魂：复刻**。不是"生成新东西"，而是"看到的，你也能做"。

## 目标用户（MVP）

聚焦两类典型用户：

1. **做短视频脚本封面的自媒体运营**
   - 触发场景：刷到爆款封面 → 想用同款风格做自己下一条内容的封面
   - 核心痛点：自己写 prompt 出来的封面不上档次，影响点击率

2. **做角色概念图的独立游戏策划**
   - 触发场景：看到爆款角色概念图 / 盲盒手办图 → 想用同款风格做自己游戏的角色草稿
   - 核心痛点：找不到合适的画师，自己 AI 生图风格不统一

**起步主题**：游戏角色概念图 + 盲盒手办风（双主题起步）。

**明确不服务**：
- 已熟练写 prompt 的 AI 创作老手（让他们继续用 Midjourney）
- 企业 / 团队协作场景
- 开发者 API 调用方
- 把生图当玩具的轻度爱好者

## 为什么先做图片复刻（不做视频）

按重要性排序：

1. **闭环最短**：5–15 秒出结果，4 周内能验证假设。视频出图分钟级，反馈循环慢一个数量级。
2. **成本可控**：单图 $0.003–$0.05；单段视频 $0.2–$2。
3. **技术栈是视频的子集**：图片复刻跑通后，视频复刻只是新增 provider + 任务类型，架构不重写。
4. **图片是视频的上游**：用户工作流天然是 *选图 → 让它动起来*。先把图做好，视频是顺势加功能。
5. **图片市场已验证**：图文封面、概念图、手办图——这类需求有大量真实证据（详见 PRD）。

## 为什么不是通用文生图

按重要性排序：

1. **大厂红海**：Midjourney / 即梦 / Liblib 已经把"自由 prompt 文生图"做到极致，新品牌没差异化抓手。
2. **真实痛点不在"生成"**：用户痛点是"复刻不出来"，不是"生不出图"。供给端不缺图，缺的是"我看到的同款"。
3. **prompt 是用户的负担**：MVP 用户调研显示"反复调 prompt 半小时还偏"是普遍现象——这是产品要解决的问题，不是要让用户学的事。
4. **复刻天然为视频铺路**：复刻是动作语义，"复刻一张图"和"复刻一段视频"在产品形态上一致；自由生成则是图片和视频两套独立产品。

## 成功指标（MVP 阶段）

| 指标 | 目标 |
|------|------|
| 上线时间 | W6 内公开 beta |
| 4 周内"完成 1 次成功复刻"用户占比 | ≥ 30% |
| 7 日留存 | ≥ 20% |
| 文生图 P50 出图时间 | ≤ 15 秒 |
| 任务失败率 | ≤ 5% |
| W6 末真实用户 | ≥ 50 个完成至少 1 次生成 |

**复刻成功定义**：用户在选中模板后完成 1 次生成，且在结果展示后 60 秒内未点击"重试"按钮。

## 设计哲学

- **可落地优于完美**：先有能跑的产品，再谈优化
- **架构留扩展点，代码不提前写**：Provider 抽象、Job type 枚举从第一天就有
- **绝不并行多方向**：MVP 未稳定前不写一行视频代码
- **不给用户写 prompt**：MVP 严格禁止自由 prompt 输入；产品价值就是"用户不需要懂 prompt"
- **复刻精度 > 创意发散**：同模板 + 同关键词产出应在视觉上接近原图
