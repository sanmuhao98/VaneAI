# 08 · 明确不做（Non-Goals）

> 这一节是项目最重要的纪律。下面任何一项做了都会显著拖慢 MVP 上线。
>
> 每条都列了 **为什么不做** 和 **什么时候才考虑**。

## 产品类

### ❌ 支付 / 订阅 / Stripe
- **为什么不做**：MVP 不验证付费意愿，先验证产品价值；接入 Stripe 至少 3 天 + 合规复杂度
- **什么时候做**：W6 后，且日活 ≥30 + 多个用户主动询问付费

### ❌ 社区 / 广场 / 点赞 / 评论
- **为什么不做**：不是 MVP 护城河；引入审核、举报、屏蔽一整套
- **什么时候做**：付费稳定后，且产品方向明确做"创作社交"

### ❌ 团队 / 工作区 / 协作
- **为什么不做**：B 端比 C 端复杂 10 倍（权限、审计、发票）
- **什么时候做**：单用户产品 PMF 验证后

### ❌ 移动端 App / 小程序
- **为什么不做**：Web 响应式覆盖 80% 场景；iOS/Android 双端意味双倍工作量
- **什么时候做**：日活 ≥1k 且 50% 用户来自移动端

### ❌ 多语言 i18n
- **为什么不做**：早期用户聚焦中文圈或英文圈即可；i18n 框架引入后每次文案改动成本翻倍
- **什么时候做**：DAU 跨地区分布显著时

### ❌ Prompt 优化器 / AI Agent 编排
- **为什么不做**：用户要的是"能用"，不是"很 AI"；优化器准确性差易劝退
- **什么时候做**：基础生成稳定后，作为高级功能

## 技术类

### ❌ 自建 GPU / 推理 / 模型
- **为什么不做**：每月最低 $500+ GPU 成本，且需要 ML Ops；外部 provider 单图成本可控
- **什么时候做**：MAU ≥1k 且每月 provider 账单 > 自建成本

### ❌ Redis / Memcached
- **为什么不做**：Postgres 在 MVP 流量下足够；Redis 增加运维 + 一致性问题
- **什么时候做**：明确出现 Postgres 瓶颈（如 P99 查询 >100ms）

### ❌ 自建任务队列 / Worker（Bull / RQ / Celery）
- **为什么不做**：Inngest 已托管解决；自建意味着部署 worker 进程 + 监控
- **什么时候做**：（基本不会，Inngest 已经够用到很大规模）

### ❌ 微服务 / k8s
- **为什么不做**：单体 Next.js + Inngest 在百万 DAU 之前都够用
- **什么时候做**：单体出现明显边界（如某模块独立扩缩容需求）

### ❌ 多 Provider 智能路由 / 负载均衡
- **为什么不做**：MVP 一家 provider 已能跑通；路由策略复杂度高
- **什么时候做**：单 provider SLA 出现问题，或成本差异显著

### ❌ ControlNet / LoRA / Inpainting / 模型训练
- **为什么不做**：每个都引入大量参数 UI + 后端复杂度；MVP 用户用不上
- **什么时候做**：基础生成 PMF 后作为 Pro 功能

### ❌ 实时协作（Yjs / Liveblocks）
- **为什么不做**：单用户产品不需要
- **什么时候做**：做团队协作时一起做

### ❌ OpenTelemetry / Grafana / Prometheus
- **为什么不做**：Sentry + Vercel Analytics + Supabase logs 在 MVP 阶段足够
- **什么时候做**：自建观测栈成本低于现有 SaaS 时

### ❌ GraphQL
- **为什么不做**：REST + Zod 已经很顺；GraphQL schema + resolver 边际收益不足
- **什么时候做**：（极不可能，除非客户端需求复杂到 REST 难以支撑）

### ❌ 复杂 RBAC / 权限矩阵
- **为什么不做**：user + admin 两个角色够用半年
- **什么时候做**：B 端或团队功能时一起做

## 流程类

### ❌ 完整 BDD / Cucumber
- **为什么不做**：维护成本高；Playwright 描述行为已足够
- **什么时候做**：（基本不会）

### ❌ 100% 测试覆盖率追求
- **为什么不做**：80% 是经验最优点；追 100% 覆盖会写大量没有信号的测试
- **什么时候做**：永远不

### ❌ 提前接 CDN / 多区域部署
- **为什么不做**：Vercel + Supabase 自带 CDN；MVP 流量 1 个区域够
- **什么时候做**：跨大洲用户占比显著

### ❌ 详细产品 PRD 文档
- **为什么不做**：本 docs 已是 PRD 替代；过度文档化会拖慢迭代
- **什么时候做**：团队 ≥5 人时

## 视频方向（V2 预留区）

### ❌ 在 MVP 期间写任何视频代码
- **为什么不做**：架构留好扩展点（`generation_type` enum、Provider 接口）即可；并行做两个方向必然两边都做不好
- **什么时候做**：W7（MVP 上线后）

### ❌ 提前做视频 UI 占位
- **为什么不做**：占位会让用户期望落空，且增加 QA 面
- **什么时候做**：V2 实际开发时
